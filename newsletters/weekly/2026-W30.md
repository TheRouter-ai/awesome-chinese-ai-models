# This Week in China AI Models (2026-W30)

**Period:** July 14 – July 20, 2026

**Overview:**
Week 30 was led by Tencent Hunyuan's embodied-AI release: **Hy-Embodied-RxBrain-1.0**, a roughly 6.2B multimodal foundation model for embodied cognition, plus a companion **Hy-Embodied-VLM-1.0** checkpoint. The release is notable because it goes beyond image/video understanding into world-state prediction and interleaved planning: the model can answer questions over scenes, imagine near-future frames, and produce subgoal plans that mix language actions with visual goal states. Elsewhere, Qwen Code shipped v0.19.10 with multi-workspace support, web-shell improvements, more resilient session recovery, and richer subagent/SDK controls, while OpenBMB updated UltraEval-Audio for audio-model evaluation.

## New Models & Releases

**Tencent Hy-Embodied-RxBrain-1.0** — Tencent published **[Hy-Embodied-RxBrain-1.0](https://huggingface.co/tencent/Hy-Embodied-RxBrain-1.0)** with the official **[Tencent-Hunyuan/Hy-Embodied-RxBrain-1.0](https://github.com/Tencent-Hunyuan/Hy-Embodied-RxBrain-1.0)** repository. The project describes RxBrain as a unified multimodal foundation model for embodied cognition, combining visual-language reasoning, near-future world-state prediction, and joint subgoal planning. The repository says the release includes the technical report, inference code, model weights, RxBrain-Bench, and fine-tuning code for VQA, multi-frame generation, and interleaved generation.

**Tencent Hy-Embodied-VLM-1.0** — Tencent also added **[Hy-Embodied-VLM-1.0](https://huggingface.co/tencent/Hy-Embodied-VLM-1.0)**. The model card metadata tags it for embodied AI, vision-language modeling, robotics, spatial reasoning, and image-text-to-text use. In context, it looks like the vision-language counterpart to the broader RxBrain embodied-cognition release.

**BAAI Orca-4B** — BAAI published or updated **[Orca-4B](https://huggingface.co/BAAI/Orca-4B)**. The draft metadata is limited, but the model card is tagged with Apache-2.0 licensing and an associated arXiv reference. It is a smaller release than Tencent's embodied-AI models this week, but still worth tracking as part of BAAI's active model-card updates.

## Embodied AI & Evaluation

**RxBrain pushes toward multimodal world models** — The RxBrain release is the week's most strategically interesting item. Its advertised tasks cover three layers of embodied intelligence: understanding current observations, predicting what actions do next, and decomposing goals into interleaved language and visual subgoals. That is a useful signal for the Chinese model ecosystem: embodied-AI releases are starting to package not only VLM checkpoints, but also benchmarks, inference paths, and generation/planning examples around physical-world interaction.

**UltraEval-Audio** — OpenBMB updated **[UltraEval-Audio](https://github.com/OpenBMB/UltraEval-Audio)**, a benchmark framework for audio-model evaluation across speech understanding, speech generation, ASR, TTS, audio codec, and audio-LLM tasks. The repository highlights ACL 2026 publication, isolated runtime support for model-specific dependencies, one-click benchmark management, replication support for popular models, and broader specialized audio-model coverage.

## Tooling & Ecosystem

**Qwen Code v0.19.10** — Qwen released **[Qwen Code v0.19.10](https://github.com/QwenLM/qwen-code/releases/tag/v0.19.10)**, plus preview and nightly builds during the week. The headline changes are operational rather than model-level: multi-workspace support across ACP transport, daemon workers and split-view sessions; a better web shell with an artifact/review panel and updated settings/sidebar; more robust session and model recovery around malformed streams, OAuth expiry and daemon restarts; richer subagent visibility; and SDK/daemon controls for effort, models, usage, context and runtime channels.

**Qwen Code Docs** — Qwen also added **[qwen-code-docs](https://github.com/QwenLM/qwen-code-docs)**, described as a documentation translation tool for Qwen Code. It is a small ecosystem addition, but it fits the broader pattern of Qwen Code moving from a CLI-oriented assistant into a larger product surface with docs, web shell, SDK, channels and automation hooks.
